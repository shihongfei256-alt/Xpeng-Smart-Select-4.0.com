## 这是什么

SmartSelect 4.0 是我独立做完的一个 AI 购车金融咨询 Demo。买车办分期时遇到的问题——政策口径、方案能不能做、流程怎么走——你用一句自然语言问它，它给出答案，并且**每条答案都带出处**，能点开核对原文。

它的思路是「大模型不拍板」：政策类问题走知识库检索，方案类问题走规则引擎判定，大模型只负责理解你的问题、抽取信息、组织语言。这样答案要么来自原文，要么来自规则，模型编不出花来。页面上能看到每次检索和判定的过程——我想让人看清「答案是哪来的」，而不是只看到一个黑盒。

> 页面内的知识库和规则是我自己整理的示例数据，用于演示交互逻辑。真实机构政策随时在变，办分期请以实际机构的合同与官方口径为准。

## 为什么做这个

因为陪家人买车办分期时真的被绕晕过：同样的方案，问不同的人能得到不同口径；想确认一条规则——比如营运车能不能做、某类资质行不行——要翻各种资料，翻到了也说不清出处；政策文件又厚又散，普通人根本没精力逐条核对。

所以我就针对这个痛点做了一个 demo：把知识库人工结构化（每条规则都标了来源章节），让大模型只做理解和检索，判定交给规则引擎，回答必须带出处。从知识库构建、规则 DSL 设计，到检索排序和兜底策略，每一层我都亲手写过、亲手调过。这个仓库就是结果。

## 快速开始

**方式一：什么都不用装。** 打开 <https://shihongfei256-alt.github.io/Xpeng-Smart-Select-4.0.com/>，直接问就行。

**方式二：在本地跑。**

```bash
git clone https://github.com/shihongfei256-alt/Xpeng-Smart-Select-4.0.com.git
cd Xpeng-Smart-Select-4.0.com
```

然后双击 `index.html` 用浏览器打开；或者起一个本地服务：

```bash
python -m http.server 8080
# 浏览器打开 http://localhost:8080
```

纯静态页面，无需安装依赖、无需任何 API Key，打开即用。

答案会标注来源章节；方案咨询会给出推荐结果和**为什么**——命中了哪条规则、卡在哪条约束。

## 它是怎么工作的

一句话概括：**提问 → 意图路由 → 检索 / 规则判定 → 带引用的回答**。

**四类能力：**

| 能力 | 干什么 |
|---|---|
| 政策问答 | 从知识库向量检索相关条文，答案附原文片段和章节引用 |
| 方案咨询 | 描述情况（期限 / 首付 / 资质 / 需求），规则引擎按准入规则判定并排序推荐 |
| 流程跟进 | 流程类问题给出真实口径、跟进路径和话术模板 |
| 图片识别 | 上传征信 / 订单 / 审批截图，视觉模型读图后参与理解 |

**三层结构：**

1. **意图理解** —— 模型判断问题属于哪类，该检索还是该走规则；从自然语言里抽取关键信息（期限、首付、资质等）。
2. **工具执行** —— 向量检索、规则引擎、视觉模型各司其职，执行结果作为上下文返回。
3. **安全兜底** —— 这是我在设计上花心思最多的部分，见下一段。

## 亮点

- **判定交给规则，不让模型发挥。** 涉及"能不能做"的结论全部来自规则引擎，模型只负责理解和表达。金融场景里，编一条准入结论是会害人的。
- **答案可追溯。** 结构化答案带章节引用，检索答案附原文片段，用户自己就能核对。
- **知识库未命中就直说。** 检索不到的宁可回答「这条我不确定」，不硬编。
- **可降级。** 不配任何 Key 也能完整运行——自动降级为「检索 + 规则模板」回答，侧栏会如实告诉你当前处于降级模式。
- **只出建议，不替人决策。** 人是最终决策者，AI 只负责把信息摆清楚。

## 技术栈

线上是纯前端静态页面，打开即用；背后的知识库是用这套流程构建的：

`知识文档 → 人工结构化提取规则（JSON DSL，带来源行号）+ 文本分块 → 向量化（LangChain + Chroma + BAAI/bge-small-zh）`，视觉理解用 DeepSeek 视觉推理模型，规则引擎是一套自己设计的 JSON 规则 DSL，配了 60 项断言测试。
