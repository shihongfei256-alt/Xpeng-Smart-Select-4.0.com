Architecture

一句话：LLM 只做理解，判定永远走规则

这是整个设计里最关键的一条边界。金融场景里，模型的「 plausible 」就是风险； 所以抽取交给模型，判定交给规则，引用交给知识库。

01 输入

自然语言

FI 描述客户情况或提问，可附带截图。

02 理解

事实抽取

正则 + 词表确定性抽取，LLM 兜底且需原文回验。

03 路由

意图路由

有客户画像 → 方案咨询；否则 → 政策问答。

04 判定

规则引擎

机构准入 + 需求约束 + 匹配度排序，逐条附依据。

05 输出

可解释答案

带来源、带置信度，低置信度主动降级。

模型可以做什么

  • 从复杂表述里抽取客户画像（年龄 / 期限 / 首付 / 征信 / 资质 / 需求）
  • 读取截图中的文字与数字
  • 把规则输出润色成人话

模型绝不能做什么

  • 编造机构政策
  • 替代规则引擎做准入判定
  • 替代 FI 决策 / 直接操作订单 / 联系客户
